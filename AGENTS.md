# OPM Toolset project instructions

These instructions apply to the entire repository, every branch, and every agent
session. Read the relevant parts of `CLAUDE.md`, when present, for the project's
architecture and implementation conventions before changing code.

## Git identity and attribution — user's project rule

Every new commit must have **Ziqiang Huang** as both author and committer, using
either `ziqiang.huang@embl.de` or `hzq.fox@gmail.com`. Credit no other person,
agent, tool or bot in commit messages or pull request descriptions.

- Use the configured identity. Never pass `--author` or override
  `GIT_AUTHOR_*` / `GIT_COMMITTER_*` to a different identity.
- No `Co-authored-by:`, `Signed-off-by:` or other `*-by:` trailer may name anyone
  else, even with an approved email address. No `Generated with ...` or
  `Generated by ...` attribution lines in commits or PR descriptions.
- Never bypass the hook with `--no-verify` or another hooks path. Correct the
  identity/message if it rejects a commit. Do not rewrite existing history merely
  to apply this rule.
- `scripts/git-hooks/commit-msg` enforces commit identities and messages. PR
  descriptions must also be checked by the session creating them; Git hooks do
  not inspect PR descriptions.
- In a new clone, and after changing the hook, run
  `powershell -NoProfile -File scripts/setup-git.ps1`. It configures **only this
  repository**, preserves an already approved email, and installs the hook in
  the clone's Git hooks directory. Git does not copy hooks when cloning.
- Verify `git var GIT_AUTHOR_IDENT`, `git var GIT_COMMITTER_IDENT` and the installed
  hook before committing. Both the name and email must satisfy this rule.

## Working conventions

- Inspect `git status --short --branch` before changes; preserve unrelated work.
- Java must remain compatible with the repository's Java 8 toolchain.
- After behavior changes, run `mvn clean test`; enable the relevant optional
  GPU/data tests and report skipped coverage accurately.
- Always package with `mvn clean package -DskipTests`, because the IDE also writes
  to `target/classes`. Preserve needed verification evidence before `clean`.
- Read `docs/manual/tools/README.md` before manual work. Edit only manual sources
  under `src/`, `assets/` or `tools/`, then regenerate the built pages.
- Long operations use the shared `Shutdown` cancellation mechanism. Keep owned
  GPU buffer cleanup scoped to the operation; do not clear a shared context on
  success.
- Do not install into or modify a Fiji installation unless the user requests it.
