Online Deskew View (BDV)

Look at a raw oblique plane microscopy acquisition deskewed in BigDataViewer - while it is still being acquired, without deskewing, converting or writing anything first.

1 · A single raw volumeOne TIFF, or the image you have open in Fiji 2 · Follow a live acquisitionA growing time lapse, played as it arrives 3 · Two files, four sourcesTwo channels, both camera halves, as one movie

What it does

The viewer reads the raw volumes the microscope writes - TIFF files in a folder - and shows them deskewed in BigDataViewer. The deskew, the mirroring of one camera half onto the other, and the alignment between channels are applied while the picture is drawn. The raw files are only read, never changed, and nothing is written to disk.

  • It follows a folder that is still filling up: each new time point appears once its file is complete.
  • It shows several files per time point - for example two acquisition channels, each with a left and a right camera half - as separately coloured, aligned sources, and only ever draws one frame from one time point.
  • It plays the time points on screen as a movie, smoothly as data arrive or strictly one complete frame at a time.

Before you start

Software

Fiji, which already includes BigDataViewer, with a build of the OPM Toolset that contains this viewer. The viewer is developed on the toolset's BDV-online-deskew branch and is planned for its next release.

The raw files

  • Format: TIFF or BigTIFF, 16-bit, uncompressed, one value per pixel, each plane stored in one piece. That is what the microscope writes, and what Fiji writes with File > Save As > Tiff... for a 16-bit stack. A compressed file (for example a deflated, already-processed result) is refused, and the viewer says why.
  • Names follow the acquisition software's pattern: name_Position0001_Time000001_Channel0001_Frames_1_451.tiff
    • _Time numbers the time points; they are ordered by number, so 10 follows 9.
    • _Channel is the acquisition channel - one file per channel and time point.
    • _Position is the stage position; one view shows one position.
    • _Frames_a_b says how many planes the file holds (b - a + 1). The viewer uses it to tell a finished file from one still being written.
    Missing tokens are tolerated: position and channel default to 1, a folder with no _Time tokens at all is read as one time point per file in name order, and a file without _Frames opens with its depth unverified (fine for a finished folder, but such a file is not shown when it arrives during a live acquisition).
  • Deskew geometry: the acquisition's ExperimentalParameters.txt in the same folder, or the three values typed in: Z step (µm), pixel size (µm) and OPM angle (degrees).

Memory

The viewer keeps the raw data it has read in a cache budget you choose, which must fit inside Fiji's own memory (Edit > Options > Memory & Threads). The first suggestion is 40% of Fiji's maximum, and never less than 256 MB. A bigger budget keeps more time points loaded, so a movie replays faster; the view reads what it needs from disk either way.

Working in the viewer

The window is a BigDataViewer canvas with two rows of controls above it and a side panel. Sources are coloured in slot order: green, magenta, cyan, yellow, then red, blue, orange and white.

The status card

The side panel's Online Deskew card says what the view is showing: the folder, the deskew geometry and where it came from, the sources, the current time point and the state of each of its files, and a count of the folder's files - complete, still being written (k of n planes), failed, changed or deleted.

A file is shown only after it has been checked: a complete TIFF with as many planes as its name promises. A file that changes after it was shown is withdrawn and checked again; a deleted one disappears; a late file with an older time number takes its place in order.

To finish, close the window; that releases the memory. Quitting Fiji closes it too.

1 · A single raw volume

The viewer reads from a folder, so a single volume needs a folder of its own.

  1. Make a folder for it. Copy the raw TIFF into a new, empty folder. Every TIFF in the folder is treated as part of the acquisition, so keep other files out.
  2. Keep the acquisition's name if it has one (…_Frames_1_451.tiff), so the plane count can be verified. Any name works; without _Frames the file opens with its depth unverified.
  3. Bring the geometry. Copy the acquisition's ExperimentalParameters.txt next to the file, or plan to choose parameters from: manual and type Z step, pixel size and OPM angle.
  4. Open the folder with Open Raw Acquisition...: position 1, acquisition channel 1, combine unticked, your flip, and an alignment CSV if you have one. The two camera halves appear in green and magenta, one mirrored onto the other.
  5. Optional - the whole camera width. To see the full width with both halves where the camera recorded them, tick combine matching _Channel#### files, set the 1st channel to _Channel0001-whole and the 2nd to - (skip).

The image open in Fiji. The viewer cannot take an image that is already open; it reads files. Save the raw, 16-bit stack with File > Save As > Tiff... into an empty folder and open that folder as above. If you want a deskewed copy of the open image rather than a view of it, Deskew Image does that.

2 · Follow a live acquisition

The viewer can watch the acquisition folder while the microscope fills it, and show each new time point as soon as its file is complete - a growing movie, with nothing written.

  1. Let the first volume finish. Opening needs at least one complete file, and the acquisition's ExperimentalParameters.txt (or the manual values). An empty folder is refused.
  2. Open the acquisition folder with Open Raw Acquisition..., as in the other recipes.
  3. Tick Follow latest to jump to each new time point as it completes, or press Play with Loop to keep playing the movie as it grows. A file still being written shows in the status card as k of n planes and appears once it is whole.
  4. Pick the mode. Completed frames shows only whole time points and never skips one; Progressive reacts faster and sharpens as data arrive.

Writing results at the same time. Run Deskew Live in the same Fiji to write deskewed OME-Zarr or TIFF while you watch. Live Deskew then tells the viewer the moment it accepts each file, so the viewer shows it at once instead of first waiting for the file to stay unchanged for a few seconds.

Live files need the full name. A file without a _Frames_a_b token cannot be checked for completeness, so one that arrives during the acquisition is not shown. Watching a folder also reads from the disk the microscope is writing to; a generous cache budget keeps rereads down.

3 · Two files per time point, four sources, as a movie

A typical two-channel acquisition writes two files per time point, _Channel0001 and _Channel0002, each holding a left and a right camera half. Each half becomes its own source.

  1. Tick combine matching _Channel#### files. The channel slots become active (the acquisition channel field is greyed: the slots decide).
  2. Fill the slots. Press + until four show, then choose _Channel0001-left, _Channel0001-right, _Channel0002-left, _Channel0002-right. Slot order is the display order and the colour. Any slot can be - (skip), and the order is yours.
  3. Choose the flip - which half is mirrored onto the other in every file.
  4. Give the alignment. For two files, use a tagged CSV from Utilities > Channel Alignment, measured on beads and naming each half against one reference (for example _Channel0001-left). Every source then takes its own matrix, and the same CSV is right for either flip. A plain 2×3 CSV only aligns each file's mirrored half onto its other half; it does not bring file 2 onto file 1.
  5. Open, then play. Choose Completed frames, set fps, tick Loop, press Play. Every frame is drawn from one time point - all four sources together - however fast you scrub.

Only the files you select are waited for. A time point appears once every selected file is complete; until then the status card names the one that is missing, for example _Channel0002: missing file. Files no slot asks for never hold anything up - choosing channels 2 and 4 does not wait for 1 or 3.

Whole widths instead of halves. _Channel0001-whole and _Channel0002-whole show each file's full camera width with both halves where the camera recorded them, never mirrored. They take a matrix only if the tagged CSV has one for that whole width. Whole widths and halves can be mixed.

Memory. Four sources from two files read twice as much per time point as one file. Raise the cache budget if Fiji allows it; for example 4000 MB in an 8 GB Fiji.

Saving a movie

The viewer plays the movie on screen; it does not write a movie file. To keep one, write the results with Batch Processing > Deskew or Deskew Live, open the projection movie in the OPM Data Viewer (Open as: projection movie), and save it with Fiji's File > Save As > AVI....

In a macro

The dialog can be recorded with Plugins > Macros > Record.... The four-source movie of recipe 3:

run("Open Raw Acquisition...", "raw=[D:/data/two_channel_timelapse] position=1 acquisition=1 parameters=[ExperimentalParameters.txt in the folder] z=0.265 pixel=0.116 opm=33.5 flip=[flip right half onto left] align=[D:/data/beads/alignment.csv] interpolation=trilinear cache=4000 combine 1st=[_Channel0001-left] 2nd=[_Channel0001-right] 3rd=[_Channel0002-left] 4th=[_Channel0002-right] 5th=[- (skip)] 6th=[- (skip)] 7th=[- (skip)] 8th=[- (skip)]");

A single volume, geometry typed in and no combining - leave combine out of the options:

run("Open Raw Acquisition...", "raw=[D:/data/one_volume] position=1 acquisition=1 parameters=manual z=0.265 pixel=0.116 opm=33.5 flip=[flip right half onto left] align=[] interpolation=trilinear cache=2000");

A macro that leaves a channel slot out gets the slot the dialog last remembered. Name every slot you combine, and set the ones you do not want to [- (skip)], as above.

  • The viewer reads files on disk; it does not show an image that is only open in Fiji.
  • One view shows one stage position.
  • It shows; it does not save. Results and movies come from Batch or Live Deskew and the OPM Data Viewer.
